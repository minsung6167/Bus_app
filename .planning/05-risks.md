# 05. 위험 식별 및 대응 방안

> 작성: AI Agent 자동 생성 / 본인 검토 완료 (2026-05-21)

---

## 위험 1: 카카오·네이버 소셜 로그인 SDK 처음 연동

- **카테고리**: 기술
- **발생 가능성**: 높음
- **영향도**: 중간
- **대응**:
  - 예방: 연동 전 하루 탐색(spike) 시간 확보, 공식 문서 버전 확인
  - 발생 시: 기한 내 구현 안 되면 이메일 로그인만으로 제출 범위 축소
- **모니터링 지표**: 카카오/네이버 SDK 빌드 성공 여부

---

## 위험 2: 기말고사 시험기간으로 2주 공백

- **카테고리**: 일정
- **발생 가능성**: 높음
- **영향도**: 높음
- **대응**:
  - 예방: 학사 일정 역산해 Must 기능 먼저 완성, 시험 전 핵심 기능 잠금
  - 발생 시: Could 기능 전면 포기, Must만 제출
- **모니터링 지표**: WBS 완료율 주 1회 점검

---

## 위험 3: 실시간 좌석 조회 불가 (독점 유료 서비스)

- **카테고리**: 외부 의존
- **발생 가능성**: 확실 (이미 확인됨)
- **영향도**: 중간
- **대응**:
  - 예방: 결정적 난수(seed) 기반 좌석 시뮬레이션으로 대체 구현
  - 발생 시: 발표 시 "실제 API 연동 시 대체 가능한 구조"로 설명
- **모니터링 지표**: 시뮬레이션 좌석 배치 정상 동작 여부

---

## 위험 4: 바이브코딩으로 인한 코드 이해도 부족

- **카테고리**: AI 의존
- **발생 가능성**: 높음
- **영향도**: 높음 (발표 Q&A 직결)
- **대응**:
  - 예방: 핵심 함수(`_resolveRegion`, 좌석 seed, 결제 유효성) 직접 주석 달고 설명 연습
  - 발생 시: 발표 전 교수님 예상 질문 5개 뽑아 답변 준비
- **모니터링 지표**: 핵심 함수 3개 구두 설명 가능 여부

---

## 위험 5: 발표 당일 네트워크 장애

- **카테고리**: 결과물
- **발생 가능성**: 중간
- **영향도**: 높음
- **대응**:
  - 예방: 개인 핫스팟 준비 + fallback 로컬 데이터 강제 활성화
  - 발생 시: 오프라인 모드로 전환, 로컬 데이터로 데모 진행
- **모니터링 지표**: 발표 전날 오프라인 환경 테스트 완료 여부
